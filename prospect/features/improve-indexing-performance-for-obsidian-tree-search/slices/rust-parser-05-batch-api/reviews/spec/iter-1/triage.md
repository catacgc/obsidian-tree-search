- [x] [Suggestion] **Consider computing `precomputedTokens` only on root items + their nested children, not the full flat list** — While technically correct that non-root items in the flat list have their tokens wasted after step 7 filtering, this computation happens entirely within a single WASM call with no boundary crossing overhead. The cost is CPU time running `parse_tokens` on short text strings in Rust (microseconds each). For a 2000-note vault with ~20 items/note, this saves at most ~20,000 cheap in-Rust string parses — negligible compared to the overall parse cost. The added code complexity (filter-first + recursive-convert) is disproportionate to the gain, and this is a premature optimization better deferred to the benchmarks slice (08) if profiling reveals it matters.
- [x] [Suggestion] **Spec doesn't exercise the `parse_single_file` fallback path for invalid/empty content** — The Rust unit test (#13 in Task 3) explicitly covers "Empty file (no frontmatter, no list items) → valid empty structure." Additionally, the spec's "Batch Output Conformance" requirement runs ALL integration test fixtures through both parsers and asserts deep equality, which implicitly covers edge cases. The behavioral contract for empty input is also implicitly defined by TS conformance (the native parser must match TS output for any input). The gap is documentation-level, not a design risk.
